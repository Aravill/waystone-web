# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Waystone Web: Go (stdlib `net/http`, SQLite via `modernc.org/sqlite`, local username/password auth) backend + plain HTML/JS frontend in `./static` (no build step; Alpine.js vendored at `static/vendor/`). MVP scope and progress: `docs/mvp.md`.

## Commands

- `.env.example` must list every env var the code reads (`os.Getenv`), with required/optional and defaults. Update it whenever you add, rename, or remove one, and keep `docker-compose.yml`'s `environment:` in sync.
- Run locally: `go run main.go` → http://localhost:8080. Set `SESSION_SECRET` (required, ≥32 chars, e.g. `openssl rand -base64 32`; the server exits without it) and `ADMIN_PASSWORD` per `.env.example`; without `ADMIN_PASSWORD` the server starts but the admin can't log in. Add `SEED_DEMO_DATA=1` to get demo users/campaigns/sessions on an empty DB (users `testy`/`roy`/`adam`/`simon`, password in `config.InitialPasswords`); off by default, local dev only.
- Verify changes: `go build ./... && go vet ./...`. Frontend E2E tests use Playwright in `e2e/`: `npm ci`, `npx playwright install chromium` (once), `npm run test:e2e`. They start their own server on port 18080 with a throwaway DB in `e2e/.tmp` (via `DB_PATH`) and never touch `./data`. PRs to `main` can't merge unless the `playwright` check (`.github/workflows/e2e.yml`) passes. There are no Go tests or linters; add E2E tests only for stable, high-value flows.
- `./deploy.sh` deploys production (app + Caddy HTTPS for waystone.aravill.org via `docker compose --profile prod up -d --build`) and keeps the data volume; never run `docker compose down -v` against data worth keeping (it wipes the SQLite volume). SQLite snapshots go to `./backups` (`BACKUP_DIR`).
- For local Docker testing use `/deploy-local` (`up`/`down`/`status`), not `docker compose up`: plain compose names the project after the folder, so every worktree leaves its own image and volume behind.
- Static files are copied into the Docker image, so frontend changes need `docker-compose build --no-cache`.
- Local DB lives at `./data/waystone.db` (gitignored); `DB_PATH` overrides it.

## Architecture gotchas

- Routes are registered in `api/router.go` (not `main.go`, despite the README). `/` is auth-wrapped and serves `dashboard.html` (Home, fed by `GET /api/agenda` in `api/agenda.go`), so every root-level JS/CSS file a page loads must get its own `http.HandleFunc` entry there, or be referenced under `/static/...`. Home also loads `/campaigns.js` for the shared helpers (`replyWord`, `zoneAbbr`, `formatShortDate`, `userAvatarHtml`).
- App version is baked in at build via ldflags (`config.Version`, `APP_VERSION` build arg). The Deploy workflow computes it from the PR-title prefix (`feat/` bumps minor, else patch) and tags after a successful deploy, so keep the `feat/` prefix accurate.
- DB access goes through the `Store` interface in `db/store.go`: add the method to the interface, implement it on the SQLite store, and expose a package-level wrapper in `db/` that calls `GetStore()`.
- Protect routes with `middleware.AuthMiddleware`; use `middleware.GetSession()` / `ClearSession()` for session state.
- Accounts start with no password (`password_hash=''`, `must_change_password=1`). Admin create and reset call `issueInvite`, which returns a one-time token valid for 7 days; only its SHA-256 hash is stored in `password_invites`, one per user. `/invite/` and `/api/invite/` are public, outside `AuthMiddleware`. An invite is valid because its row exists, never because of `must_change_password`, and `/change-password` only remains for users still holding an old temporary password.
- `AuthMiddleware` adds `?next=<page>` when redirecting a logged-out page request, and `login.html` only follows it if it's same-origin. Page loads (not API calls) renew the session cookie at most once a day via `renewed_at`.
- User display name precedence: `Nickname` → `Name` → `Username` (`User.DisplayName()`). API responses that reference users keep raw IDs and add enriched `*_user` / `*_users` objects (mirror the campaigns API).
- Session responses are one per `(session_id, user_id)` (upsert); pending players are computed from the campaign's player list.
- When changing `models/user.go`, update seed data in `config/config.go` and keep `SaveUser` and the `SELECT`/`Scan` sites in `db/sqlite_store.go` in sync.
- The `ADMIN_USERNAME` user is env-managed: password reset from `.env` on every start; can't be blocked, deleted or demoted.
- The session cookie is `Secure` by default (`SESSION_COOKIE_SECURE`): fine on `http://localhost`, but over plain HTTP on a LAN IP login returns 200 and the cookie silently never sticks; set it to `false` there.
- Journal entries key on the session id (`journal_entries.session_id`), never on a session number: numbers are positional (`campaignSessionSummaries`, computed per request) and shift when a session is recorded, deleted, re-dated or cancelled, so never store one (not in a revision, notification or seed). Entries exist only for played sessions (Confirmed and ended, or by hand): `journalSession` in `api/journal.go` is the one check. Foreign keys are off, so the cascades are by hand: `DeleteCampaign` and `DeleteManualSession` delete contributors, revisions, then entries via `deleteJournalForSessions`. Saves are optimistic (`entry_id` + `base_revision`, 409 on a stale base) and the newest 200 revisions per entry are kept; credit lives in `journal_entries.author_id` and `journal_contributors`, so it survives pruning. A cancelled session's entry stays readable and deletable (`journal_cancelled` on the game API) but not editable.
- Characters: assignments are ended (`ended_at`), never deleted, on leave/kick/decline/anonymize/swap/clear. Foreign keys are off, so `DeleteCampaign`/`DeleteCharacter` delete assignments by hand, and any new code that removes a player from `campaigns.players` must end their assignments (`endUserAssignments`, same tx). A game accepts characters only when `campaignSystemID` resolves its system text to a known system. `notify` accepts a nil campaign. Design: `docs/design/characters.md`.
- Sessions with `manual=1` (the DM's "Record a past session") are chronicle-only: excluded from the month view and ICS, no replies or notifications, and may have `time=''` so `sessionStart` fails; check `Manual` before calling it.
- The Calendar button focuses the first unanswered session's month, so tests use `openCalendar`/`goToMonth` helpers, not `page.clock`.
- `api.StartSessionStartNotifier(ctx)` (started from `main.go`) runs every minute and sends one `session_started` notification per Confirmed session to its players and followers (never the DM) once it begins. The `notifications` table is the dedupe, so there is no schema or env var for it.
- Codex (`/codex`, `api/codex*.go`, `db/sqlite_codex*.go`, `static/codex*.js`): worlds are folders; `pages.world_id` `''` is the Unsorted folder (the API calls it `unsorted`). `[[Title]]` links and map pins resolve only inside the page's own world, by title or alias (compared with `NormName`, never SQL NOCASE), and are stored in `page_links.to_page_id` / `map_pins.to_page_id`. Anything that changes what a name can point at (create, rename, alias set, move, delete a page) must end its transaction with `resolveWorldLinks(tx, worlds...)` for the worlds it touches (the page's world; a move passes the old and the new one), and `loadCodexIndex` takes the same optional world filter, so a save never reloads the whole Codex; a body save only rebuilds that page's rows. Foreign keys are off: `DeletePage` removes revisions, contributors, aliases, links, pins, pin events and images by hand (the handler then removes the image files), and `DeleteWorld` is refused while a game or a page still points at it. `campaigns.world_id` is a label written only by `SetCampaignWorld`, never by `SaveCampaign`. Page saves are optimistic (`base_revision`, 409 `stale_base`), titles change only through rename (which rewrites links in the same world and adds revisions), and restoring a revision restores the body only. `codex.html` also loads `journal.js` for `diffWords`/`diffHtml`, so `codex.js` must not redeclare its top-level names. While `CODEX_ADMIN_ONLY` is on (docker-compose default; off for `go run` and `/deploy-local`), `codexGate` in `api/codex_access.go` hides `/codex*` and `/api/codex*` from non-admins, `/auth/current-user` returns `codex_access`, and `theme.js` reveals the `[data-codex]` links (which start `hidden`) only when it's true.
- Uploads: map images live in `UPLOAD_DIR` (default `uploads` next to the database file, so on the Docker data volume); files are random-named and immutable, restoring an image adds a row for the same file, and the backup job mirrors new files to `BACKUP_DIR/uploads` without deleting. CodeMirror and Leaflet are vendored by `tools/vendor` (`npm run build` there; outputs are committed under `static/vendor`, and `tools` is in `.dockerignore`).
- Log out and Profile live in the header's user menu (`<details class="user-menu">`), not the nav; every page with a nav must include it and call its own logout handler (`admin-users` uses `logout()`). `.message` is a fixed toast, so pages show it with `x-show` and `role="status"`.

## Conventions

- Go: handlers named `HandleXxx`; always set `Content-Type: application/json` and an explicit status; decode bodies with `json.NewDecoder(r.Body).Decode(&v)`; guard methods with `r.Method` checks.
- JS: `fetch()` only; wrap calls in try/catch and report via `showMessage(text, 'error')`; use `textContent` (or `escapeHtml()`) for user-generated content; init on `DOMContentLoaded`.
- Styling follows `STYLE_GUIDE.md` ("Scriptorium": parchment/candlelight themes via CSS tokens, IBM Plex Mono + IM Fell, rubric-red accent that means "you"; mock-ups in `docs/design/mockups/`). Read it before UI work. Bump the `?v=N` cache-busting query on CSS links when changing CSS.
- Keep the app lightweight and minimal: surgical changes, reuse existing helpers before adding abstractions, no broad refactors unless asked.

## Git

- Commit and push each finished logical chunk as you go, without being asked (`commit-as-you-go` skill). Never commit directly to `main`. Commit subjects: lower case, ≤6 words, **no** `feat:`/`fix:` prefixes; put details in the body. Small logical commits.
- Branches use type prefixes: `feat/...`, `fix/...`, `chore/...`; worktrees go under `.claude/worktrees/` with matching names (`feat-...`).
- PRs are squash-merged with titles like `feat/admin users`.
