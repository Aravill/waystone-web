Suggesting a poll of dates

The DM offers several dates for the next session as one poll, each date with its own start time and length. Players reply Yes / Maybe / No to each date as today. When the DM confirms one date, the others are removed, and players get one notification for the poll and one for the confirmation.

There are two ways to build the poll. The pages are live: click days, change times, remove rows.

A · Pick days on the calendar, then set the times

This grows out of today's Copy → paste mode. The DM clicks Suggest dates in the panel (or Copy on a session, which fills in its time), clicks days in the month, then Next opens one dialog with a row per day. Days in other months can be added by moving the month while picking.

1 · Picking. The bar sits at the top of the side panel, like the paste bar. Free days show a red +, picked days a ✓. Past days and days that already have a session can't be picked.

    2 · Times. One row per picked day. New rows take the first row's time and length, so the DM only changes the odd one out. The timezone is shared by every row.

    • Good: the month is in view while choosing, so clashes with other sessions and the gaps between dates are obvious. It reuses the paste mode the DM already knows, and Copy simply pre-fills the time.
    • Cost: two steps, and picking mode is one more calendar state (it already exists for paste).
    • Phones: the bar sits above the month; the dialog is a bottom sheet and each row wraps to date on top, then start and length.

    B · One dialog with rows

    The DM clicks Suggest dates (or + Suggest session on a selected day, which becomes the first row) and adds dates in the dialog itself, with a date field per row. The calendar stays as it is today, without a picking mode.

    • Good: one dialog, one step, and nothing new on the calendar itself.
    • Cost: the month is hidden behind the dialog, so the DM picks dates blind from a date field and only finds a clash (the 2nd row here) when the row turns red. Copy → paste would need its own place in this dialog.
    • Phones: native date pickers are fine on phones, but three fields per row stack into a long sheet.

    Shared by both

    • Length is one select (1h, 1h 30m … 8h) instead of today's hour and minute spinners, which are too wide for a row. Today's single-session dialog would switch to it too.
    • A poll needs at least one date; with one row the button reads "Suggest 1 date" and it behaves like today's single suggestion.
    • Adding a date to an open poll later reuses the same picking (A) or the same dialog with the existing dates locked (B).
